## 1. Arch 来源设计（哪里取 blocks/channels/board_size）

优先级（从高到低，`omigamax/train/loop.py`）：

1. `--resume` 找到 `models/latest.pt` → 其 checkpoint 记录的 `arch` 决定网络（既有行为，保留）；
2. `--init-checkpoint <path>`（新增，如 `models/pretrain.pt`）→ 该 checkpoint 的 `arch`
   胜出，模型由其权重 warm-start（P7 预训练接入主路径）；
3. `config`（b10c128 默认）+ 显式 CLI `--blocks/--channels/--board-size`（新增，覆盖 config）。

实现：
- `loop.apply_arch_overrides(cfg, blocks, channels, board_size)`：复制 cfg 并应用 CLI
  覆盖，绝不修改共享 config 对象 → `config/default.yaml` 保持 b10c128 不变。
- `loop._load_or_init(..., init_checkpoint=None)` 拆出 `_model_from_checkpoint()`
  （resume 与 warm-start 共用）：`load_checkpoint` → `create_model(ckpt arch)` →
  `load_state_dict` + `optimizer.load_state_dict`（SGD momentum 状态兼容，同一
  `make_sgd_optimizer` recipe）→ 恢复 `rng_state`/`global_step`。
- `run_loop` 新增 `init_checkpoint` 参数；`board_size` 改为取自 `model.board_size`
  （而非 config），并显式穿线到 `generate_games(size=)` 与 `_run_eval_gate(board_size=)`，
  使自对弈 / 回放缓冲 / 可视化 / 评估门都在网络的真实尺寸上运行。

## 2. Checkpoint 路径验证（models/pretrain.pt）

- `load_checkpoint(models/pretrain.pt)` 实际读取：keys = {arch, config, extra,
  format, global_step, model_state_dict, optimizer_state_dict, rng_state, version}，
  `arch = {blocks:20, channels:256, board_size:19}`，`global_step = 200`。
- 参数计数：`sum(p.numel() for p in model.parameters()) == 23,962,085`（不含 BN
  running_mean/var 缓冲；含缓冲 23,983,126）。与任务规格一致。
- **无不兼容项**：arch 键名一致；optimizer 同为 SGD(momentum=0.9, weight_decay=1e-4)
  且每步由 `set_learning_rate` 重新套用 RL 的 lr；value_head 为标准 AGZ tanh 头（无
  scale 属性，`load_state_dict` 严格匹配通过——无 missing/unexpected keys）。因此
  仅加 warm-start 路径，未改 loader/loop 的其他逻辑。

## 3. 自对弈 plumbing（CPU 验证）

- RL 循环路径：`generate_games(model, cfg, size=board_size)` 直接使用由 checkpoint
  arch 构建的模型（MCTS + BatchedNetworkEvaluator 推理同一网络）→ b20c256 网络可
  直接自对弈。
- 独立 CLI `omigamax/train/selfplay.py` 新增 `--model <checkpoint>`（如
  `models/pretrain.pt`）：其记录 arch 胜出（含 board_size），并 `load_state_dict`
  载入权重。lazy import `load_checkpoint` 规避 buffer→selfplay→train 循环导入。

## 4. 测试（tests/test_rl_adapt.py，全部 CPU-only，8 passed in ~12s）

- `TestCheckpointArchWins::test_b20c256_checkpoint_beats_b10c128_config`（a）
  假 b20c256 checkpoint → `_load_or_init` 建出 20/256/19 模型（config 为 10/128/19）。
- `TestCliArchOverrides::test_apply_arch_overrides_maps_and_keeps_config` + 
  `test_fresh_init_uses_overridden_arch`（b）显式 flags 覆盖 config，且共享 config 不变。
- `TestPretrainLoadsInRL::test_pretrain_pt_warm_start_param_count`（c）
  `load_checkpoint(models/pretrain.pt)` → arch {20,256,19} + 23,962,085 参数（CPU）。
- `TestPretrainLoadsInRL::test_pretrain_pt_optimizer_state_compatible`（c2）
  SL 的 SGD 状态可载入 RL loop 的 SGD 优化器并可做一步训练。
- `TestSelfplayFromPretrainArch::test_selfplay_net_forward_shapes`（d）b20c256 网络
  CPU 前向 → policy (1,362) / value (1,1)，参数 23,962,085。
- `TestSelfplayFromPretrainArch::test_selfplay_game_runs_on_pretrain_net`（d2）
  19x19 极小自对弈局（sims=1, max_moves=4）跑通，(s,π,z) 尺寸正确。
- `TestMicroRLRun::test_micro_run_loss_finite_and_decreases`（e）9x9 / blocks=1 /
  channels=8，自对弈 2 局 + 10 训练步（interrupt_after=10 触发中断路径、跳过 eval 门）：
  loss 5.8061 → 5.4865（finite 且下降），实测 ~5s（预算 3min 内）。
