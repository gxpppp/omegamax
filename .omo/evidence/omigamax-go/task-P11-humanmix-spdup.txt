PART 1 — HUMAN-MIX (KataGo-style (1-mix)/mix batches)
--------------------------------------------------------------------------------
DESIGN (rng / checkpoint / resume semantics)
- train_steps(model, optimizer, buffer, steps, *, ..., human_sampler=None,
  human_mix=0.0): per step human_n = round(mix*batch_size), rl_n =
  batch_size - human_n (total stays exactly batch_size, divisible by the 8x
  symmetry chunker). RL part = buffer.sample(rl_n, rng); human part =
  human_sampler(rng, human_n); concatenated into one dict {s,pi,z}.
- BOTH streams draw from the SAME persistent numpy rng, RL first then human,
  in a fixed order per step. The rng state is already persisted by
  save_checkpoint("rng_state"); NO new checkpoint fields needed -> resume is
  loss-reproducible with mixing on (verified by test_d_resume_reproducible).
- mix <= 0 OR human_sampler None OR round(mix*B)==0 -> pure-RL short-circuit,
  byte-identical to pre-P11 (the human stream is NOT advanced).
- run_loop: when human_mix>0 creates PretrainChunks(data/pretrain) read-only,
  verifies chunk board_size == model board_size (else ValueError), builds the
  sampler via make_human_sampler(chunks), passes sampler+mix to train_steps,
  closes the mmap handles at run end. CLI: --human-mix FLOAT (default 0.0),
  --pretrain-data-dir (default data/pretrain). Symmetry path: the mixed batch
  goes through the SAME augment_batch as a whole (8x) -- numpy flips/rotations
  work on the float32 mixed arrays (test_e asserts shapes 8B x 17 x N x N).

CONVERSION HELPER (omigamax/train/pretrain.py)
- PretrainChunks.board_size property (first chunk's s shape, additive).
- convert_to_rl_batch(batch): s uint8 (B,17,N,N) -> float32 value-preserving;
  pi uint16 index 0..N*N -> one-hot (B,N*N+1) float32 (index N*N=pass lands in
  the last slot); z int8 (B,) -> (B,1) float32. N derived from s.shape[-1] so
  9x9 test chunks and the 19x19 corpus both convert correctly.
- make_human_sampler(chunks) -> callable(rng, n) = convert(sample_batch(rng,n)).
- Public sampling API of PretrainChunks untouched -> cli/evaluate.py human-match
  unaffected (its 44 call sites + tests still green).

PART 2 — SELF-PLAY SPEEDUP (measure first, P10 methodology: serial runs,
        1 game x 150 sims x max_moves 150, real b20c256 models/pretrain.pt,
        nvidia-smi every 1s, startup excluded)
--------------------------------------------------------------------------------
BOTTLENECK (baseline cProfile + flush-phase timings): Python MCTS + rules
engine dominates, NOT the GPU. Old-code 150-sim game: 98.66 sims/s, GPU
forward ~4.6% of wall, python_mcts_overhead 80.8%, mean leaves/flush 5.89
(batches rarely fill to leaf_batch=16 -> raising leaf_batch can't help).
Hot spots: is_legal/is_ko 25.9s, expand/board.play 17.9s, .cpu() sync (forward
hidden inside) 10.8s, decode_policy 7.9s (re-scanned 361 legality points/leaf).

FIXES (each behavior-preserving; tests stayed green throughout):
  1. decode_policy(logits, board, color, legal_moves=None): MCTS leaves already
     carry node.legal_moves -> skip the 361-point is_legal rescan per leaf.
  2. is_legal_move empty-neighbor fast path: an empty orthogonal neighbor means
     the stone keeps a liberty -> never suicide -> legal immediately (skips the
     placement simulation + group scan for the common open-board case).
  3. has_liberty early-exit on first liberty (was building the full set).
  4. Board.play(..., check_legal=False) used by MCTS expand (actions already
     vetted by legal_actions, incl. simple-ko) -> halves per-child is_legal.
  5. is_ko_prohibited compares coords directly (no tuple() allocation, 1.6M+).
  6. fp16 self-play inference: BatchedNetworkEvaluator(..., fp16) runs the
     flush forward under torch.autocast('cuda', fp16) (no-op on CPU; eval-gate
     evaluators keep default fp16=False). Threaded from cfg "selfplay_fp16" or
     play_game(leaf_batch=, fp16=) / CLI --selfplay-fp16 / --fp16.
  7. leaf_batch threaded cfg->play_game->evaluator AND MCTS batch cadence
     (previously the evaluator saw a different cadence than run_search).
